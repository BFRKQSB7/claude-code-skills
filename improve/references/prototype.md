# 抛弃型原型

> 来源: Matt Pocock `prototype` — "原型的唯一价值是回答问题。答案才是该保留的。"

## 两分支

| 问题类型 | 做法 |
|---------|------|
| "这个逻辑/状态模型对吗？" | 终端交互 app — 手动推状态机过难用纸推的 case |
| "这个 UI 应该长什么样？" | 单路由多个截然不同的 UI 变体，URL search param 切换 + 浮动底栏 |

## 通用规则

1. **标记为抛弃型** — 文件名/路径明确这是 prototype
2. **一命令启动** — `pnpm <name>` / `python <path>` / `bun <path>`
3. **默认不持久化** — 内存状态。除非问题本身涉及数据库
4. **跳过抛光** — 无测试、无错误处理、无抽象
5. **每次操作后显示完整状态** — print/render 让用户看到变化
6. **结束后删或吸收** — 不留在 repo 里腐烂

## 收尾

把**答案**存在持久地方（commit message, ADR, issue, NOTES.md）+ 问题原文。然后删掉原型代码。

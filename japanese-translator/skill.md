# 日文轻小说翻译·校对

## 项目文件定位（每次会话开始时强制执行）

### project.txt 机制

**每次会话开始时**，按以下优先级定位项目文件：

1. **在项目根目录查找 `project.txt`**：若存在 → 读取其中所有文件路径
2. **若不存在**：询问用户"项目文件夹在哪里？"→ 创建 `project.txt` 写入已知路径
3. **若用户说"继续翻译/校对"但未指定位置**：搜索常见位置（Desktop/fanyi 等）的 project.txt

### project.txt 维护规则

| 触发条件 | 行为 |
|----------|------|
| 新建/移动/重命名项目文件 | **立即更新 project.txt** |
| 每次会话结束前 | 确认 project.txt 与实际文件一致 |

### 目录结构（路径从 project.txt 读取）

| 目录 | 含义 | 必需 |
|------|------|------|
| 原文目录 | 原始日文文本 | 是 |
| 译文目录 | 翻译后中文文本 | 是 |
| 例文目录 | 参考翻译文风 | 否 |

- `_context.json` 和 `校对清单.md` 存放在**译文目录**下
- 章节号规则：文件 N = 内容第 N-1 章（001=序章例外）

## 上下文控制

读完 `sessionChapterCount` 后按以下规则决定下一步：

| sessionChapterCount | 行为 |
|---|---|
| <5 | 自由继续，不询问 |
| ≥5 | 每章完成后强制自检；**先估算上下文余量**——若回复变慢/引用文件过多/已连续≥5章未compact，**立即暂停**输出 `建议 compact` |
| ≥8 | 自检 + 强制暂停，必须先 `/compact` |
| ≥12 | 拒绝，必须先 compact |

compact 恢复：读进度 → **强制重置 `sessionChapterCount=0`** → 继续（不询问）。

> ⚠️ **反模式**：count < 5 时不得输出"是否继续第X章？"；输出 `count = N` 后必须同一轮中立即读下一章继续。

## 新项目 Phase 0：翻译标准定稿

0. **项目命名**：用户提供小说名 → 写入 `翻译标准.txt`；未提供 → 询问用户（**禁止自行取名**）
1. 读原文样本 → 提取人物名单、术语表
2. 草拟 `翻译标准.txt` → 提交用户确认
3. **确认后立即精简**：
   - 删除 skill 引用文件已覆盖的通用规范（标点/排版/称谓/术语等）
   - **仅保留**：人物译名、特有术语（作品名/地名/国名）、特有规则（如删除作者宣传语）
   - 目标：≤50行
4. 将项目特有术语同步到 `translate.md` 对应表格

## 翻译流程

1. **Phase 0.5 预算检查**：读 `sessionChapterCount`，按上表判断
2. **弧线边界检测**：`arcCheckCounter ≥ 8` 时检查四要素（情节/角色/地点/时间），≥2项→封存旧弧线+创建新弧线
3. **定位原文**：读 `翻译进度.txt` → 下一章号 → 读 `_context.json` → 读原文
4. **译名预检**：扫描原文新人物/特殊名词 → 对照 `翻译标准.txt` → 不在清单中的提交用户确认 → 追加
5. **执行翻译**：遵循 `translate.md` 核心原则和翻译策略
6. **三步自检**：执行 `references/grep-patterns.md` 中的 grep ②③④⑤⑥ + ①通读
7. **更新上下文**：`_context.json`、`校对清单.md`、`翻译进度.txt`

## 校对流程（三阶段）

校对分三阶段——**先 grep 粗扫全量，再对安全项批量 sed，最后逐章精读**。详见 `proofread.md`。

> **实战铁律**：能批处理就批处理。grep 扫全量 → sed 一键替换 → 批量操作完再逐章精校。机翻垃圾章节直接重译。

### 阶段一：批量扫描
若 `校对清单.md` 批量扫描表为「待执行」→ 对全部章节跑六项 grep（不读正文，秒级/章）。结果填入批量扫描表。

### 阶段二：批量替换
对照 `references/grep-patterns.md` 中「可批量 sed 替换」清单执行 `sed -i`。仅替换清单中的项。批量操作不计入逐章精校统计。

### 阶段三：逐章精校（循环）
1. **预算检查** → 读 count
2. **定位译文** → 读 `校对清单.md` 下一待校对章节
3. **三步自检** → ①通读 + 执行 `grep-patterns.md` 快速执行脚本（重点查 ②a/⑥）
4. **修改** → 逐处修正
5. **更新** → `_context.json` + `校对清单.md`
6. **继续** → count<5 直接下一章 / count≥5 检查余量后询问

> ⚠️ **校对清单强制更新**：每完成一章必须立即追加一行（即使零命中）。这是新会话恢复进度的唯一依据。

## 弧线封存时

- 执行批量自检（弧线内全部章节）
- **强制清理 `_context.json`**：删除封存弧线的所有章节条目，弧线 `sealed` 设为 `true`
- 更新 `翻译进度.txt`

## 上下文文件 `_context.json`

```json
{
  "arcs": [{"id": "arc-N", "label": "篇名（范围）", "chapters": "NNN-NNN", "summary": "...", "sealed": true/false}],
  "chapters": {"NNN": {"summary": "...", "arc": "arc-N", "chars": {}, "plotFlags": []}},
  "pendingFlags": [],
  "arcCheckCounter": 0,
  "sessionChapterCount": 0
}
```

---

## 恢复翻译/校对（compact 后）

1. 读 `project.txt` → 定位所有项目文件
2. 读 `_context.json` → 确认 `sessionChapterCount` 已重置为 0
3. 读 `proofread.md`（校对）/ `translate.md`（翻译）
4. 读 `校对清单.md` / `翻译进度.txt` → 定位下一章节
5. 读译文/原文 → 开始校对/翻译
6. **记住**：count 从 0 起，<5 时每章末尾不得询问。输出 `count = N` 后同一轮立即读下一章继续。

# experiments — H3 实测记录

这个目录是 `minimax-h3` skill 的燃料来源。

## 为什么要有它

改写器每一步都在做决策：这个词会不会被拦、这张图该走 Ref2VA 还是 I2VA、这段该 350 词还是 500 词、这张卡上 8 秒能不能跑 640×352。

**决策依据只能来自实测。** 没有失败记录的改写器，手里只有通用电影词汇，于是它只会做一件事：注水。

市面上几十个视频提示词仓库收集的都是**成功的**提示词，而决策需要的是**失败的**提示词。这就是它们做不出好改写器的原因，也是这个目录存在的理由。

## 怎么用

1. 跑完一条（**无论成败**），复制 `cases/case-template.md` 建一份
2. 重点写：失败版本原文 + 症状 + 判断的病根 + 改了什么
3. 沉淀部分要**回写**：默认值补进 playbook 第 2 节，翻车条目补进第 5 节，硬件数据补进第 6 节
4. 推翻的旧假设单独标 ❌，**不要删掉旧结论**——留着才知道哪条路走过了

## 目录

```
experiments/
├── README.md          ← 本文件
├── cases/
│   ├── case-template.md
│   └── case-NN-简称.md
└── summary.md         ← 攒够 3–5 个 case 后写阶段性总结（可选）
```

## 判断一个 case 值不值得记

值得：

- 迭代 ≥2 版才通过的
- 被平台拦截的（记下**具体哪个词**）
- 本地端跑不动或跑崩的（记显存/画幅/帧数）
- **推翻了 playbook 里现有结论的**（最高优先级）

不值得：

- 一次过且没有意外的
- 纯换主题的重复实验
